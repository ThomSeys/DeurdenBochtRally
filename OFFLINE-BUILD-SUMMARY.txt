📊 TECHNICAL ARCHITECTURE
═════════════════════════════════════════════════════════════════════════════

SERVICE WORKER
──────────────
Caches:
  ├─ ddb-rally-v1     : Precached core assets
  ├─ ddb-runtime      : Runtime-cached pages
  └─ ddb-api-v1       : Cached API responses

Strategies:
  ├─ API calls      : Network-first → cache → offline response
  ├─ Navigation     : Network-first → cache → offline.html
  └─ Assets         : Cache-first → network

Features:
  ├─ Automatic API caching with smart TTL
  ├─ Background sync for offline submissions
  ├─ Offline detection & graceful fallback
  └─ Asset availability fallbacks

INDEXEDDB
─────────
Database: DeuerDenBocht (v1)
Stores:
  ├─ cache        : Cached API responses
  └─ submissions  : Queued form submissions

REACT COMPONENTS
────────────────
useFetchOffline<T>(url, options)
  ├─ Detects online/offline
  ├─ Returns cached if offline
  ├─ Auto-caches on success
  └─ Shows cache status

useOfflineStatus()
  ├─ Real-time online/offline
  ├─ Queued item count
  └─ Auto-updates

OfflineForm component
  ├─ Detects offline
  ├─ Queues submissions
  └─ Shows status feedback

🎓 KEY CONCEPTS
═════════════════════════════════════════════════════════════════════════════

SERVICE WORKER
──────────────
Runs in background, intercepts network requests, serves cache when offline,
syncs data in background even if app is closed.

INDEXEDDB
─────────
Browser database, survives app restart, stores cache & submissions,
~50MB available per origin.

CACHE STRATEGIES
────────────────
Network-first : Try network, fallback to cache (live data)
Cache-first   : Use cache, try network (assets)
Stale-while   : Return cache, update in background (leaderboard)

PWA
───
Progressive Web App - web app + native app features, installs on home
screen, works offline, auto-updates.
